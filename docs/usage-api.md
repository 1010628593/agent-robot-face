# Usage API and independent archive

The v3 Bridge serves metadata-only usage separately from the business lifecycle ledger. All read endpoints reject unexpected Host or browser Origin. Refresh requires the existing local control token; it does not change business focus, device usage browsing, credentials, or account settings.

- `GET /v1/usage?subject=current&period=today`: subject accepts current/all/codex/cursor/hermes/workbuddy, period today/7d/30d. Today is included, local host timezone. Unknown parameters are rejected.
- `POST /v1/usage/refresh`, JSON `{}`, Bearer local control token: 202 queues a coalesced refresh. This is not confirmation of new data. Query revision and collecting/status show progress and result.

The response contains version1, revision, resolved subject, period, timezone, start/end dates, as_of_ms, stale, status, error, collecting, summary, agents, history, models, model_count, quotas and sources. Nullable counts use explicit null. `summary` and each history/model/agent row provide input_tokens (inclusive of known cache components), output_tokens, cache_read_tokens, cache_write_tokens, total_tokens, actual_costs, coverage and as_of_ms. Cache components are subsets of input. Coverage is complete/partial/unknown; do not infer complete accounting from numeric values. Actual costs are grouped by ISO currency with amount, coverage and native provenance. They are never summed across currencies or estimated from model prices.

History contains one dated entry per calendar day, including unknown days with null values. Models returns the top100 by known tokens; model_count preserves the full distinct count. Quotas are keyed by provider/account_hash/window_key, with agents for shared membership. Account hashes contain no credentials or email. Quota values and freshness belong to each window, independently of historical token freshness. Available used_pct is bounded0..100; unknown percentage remains null even if a provider reports an absolute amount. Quota currency budgets do not imply actual billed fees.

`usage-v3.sqlite3` is an independent WAL database beneath the Bridge state root. Each `(date,agent,model)` is a replacement bucket. Replayed scans never increment totals. Successful authoritative full-range source snapshots remove obsolete buckets in that range; unavailable or partial exports preserve earlier archive coverage. Cursor rows retain their original official-query timestamp when cached. Oldest contributing row timestamp is returned for aggregate freshness. A failed collector keeps archived rows, marks status error, and does not fabricate new observations.

The Bridge supervises a persistent Node process with bounded JSON lines, a process-group shutdown, restart backoff and private collector cache. A fixed1500ms event merge window prevents continuous source activity from starving refresh. There is one collection at a time and at most one pending follow-up. The installer pins the installed Node executable in the user LaunchAgent. Source credentials remain in native read-only stores; none are copied into this archive or LaunchAgent.

USB v3 projects a bounded subset and a separate authoritative browsing revision; see [protocol-v3.md](protocol-v3.md). Production never falls back to simulated usage. Uninstall retains the usage archive and rollback backups, like the lifecycle ledger.
