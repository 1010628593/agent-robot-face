# Usage collector JSON protocol 1

Run with Node >=22.15.0. The standalone package has no npm runtime dependencies, Electron dependency, Hub, or dependency on the reference checkout. The bundled binary currently supports macOS arm64 only. Exact source versions and SHA256s are in `usage-collector/vendor-manifest.json`; Token Monitor 0.46.0 uses the pinned Tokscale 4.13.0 fork, not Tokscale 0.46.0.

```
node usage-collector/index.js --once --root /absolute/RobotFace/private/usage --days 30
node usage-collector/index.js --watch --root /absolute/RobotFace/private/usage --days 30
```

`--root` is mandatory, absolute, and must be the Bridge's private RobotFace state directory. The caller owns path policy. `--days` accepts 1 through 30 inclusive, with today in the host's local timezone. No source credentials or Token Monitor configuration are copied. Tokscale's generated caches live exclusively below `ROOT/tokscale`; source logs and existing native login stores remain read-only. The worker never installs hooks, refreshes credentials, starts login, or restarts apps.

Stdout emits exactly one bounded JSON object per scan, followed by newline; stderr from Tokscale is discarded. Top-level fields are `version:1`, `as_of_ms`, IANA `timezone`, `range:{since,until}`, `days`, `sources`, `quotas`, and sanitized `errors:[{code}]`. Never archive raw Tokscale stdout: it includes additional metadata that this wrapper intentionally strips. Output rows contain no prompts, session identifiers, chat payloads, file paths, account email, or credentials. At most 10,000 day rows are accepted; upstream JSON is capped at 32 MiB and 240 seconds.

`days` is a flat, sorted, deduplicated replacement snapshot keyed by `(date, agent, model)`. Agents are exactly `codex`, `cursor`, `hermes`, `workbuddy`; model may be null. Nullable nonnegative integer metrics are `input_tokens`, `output_tokens`, `cache_read_tokens`, `cache_write_tokens`, `total_tokens`. Tokscale's normalized graph reports disjoint input/cache components; this protocol makes input_tokens inclusive of known cache-read/write, so cache fields are input subsets and input_tokens + output_tokens equals total_tokens where known. Reasoning is already included in output, so it is not added again. Generic graph cost is always discarded. For Codex/Hermes/WorkBuddy graph rows, cache-write remains null because the graph parser emits zero even where native support cannot be proven. Cursor independently reads the official usage-events export: cache-write input, uncached input, cache-read and output are disjoint columns; inclusive input sums the first three. Missing source usage produces no rows and unknown coverage, never fabricated zero usage.

Each row has `actual_cost:null` or `{amount,currency,provenance}` and `coverage:{tokens,cost}`, each one of complete/partial/unknown. Hermes reads only the native `actual_cost_usd` column, accepts explicit actual/exact/reported/billed status, and requires an ended session whose start and end occur on the same local day. The amount is attached only to a matching Hermes day/model row, with USD and provenance `hermes_actual_cost_usd`; coverage stays partial. Cross-day/open sessions and estimated/unknown status remain null. Native cost currently reads the selected `HERMES_HOME` database or default `~/.hermes/state.db`; additional profile databases are not yet cost-enriched. No native actual-cost adapter exists for the other three clients. This limitation is explicit in source metadata.

`sources` entries contain `id`, `agent`, availability, reason, scalar coverage, metric_coverage, provenance, snapshot_complete and actual_cost_status. A failed scan yields empty days with unavailable sources and a sanitized error; the Bridge must preserve archived data. An empty source is not proof of zero usage. The Bridge replaces complete observed day/agent buckets, rather than incrementing old totals.

`quotas` entries contain provider, window_key, account_hash, agents, label, used_pct, used, limit, remaining, unit, reset_ms, as_of_ms, availability, reason and provenance. Unknown metrics are null. Available accounts use a SHA256 of a native account identifier, never a token; unavailable identity is null. Each account/window is account-shared and should be deduplicated by `(provider,account_hash,window_key)` across agent scopes.

Codex reads existing `CODEX_HOME/auth.json` OAuth data in memory and queries only `https://chatgpt.com/backend-api/wham/usage`. Cursor opens its native state SQLite database read-only, reads only its access token, derives native account identity, and queries only `https://cursor.com/api/usage-summary`. Redirects are rejected; request timeout is 12 seconds; errors contain no HTTP body. Neither adapter refreshes or writes credentials. Watch-mode quota probes are cached for 300 seconds; explicit refresh may bypass that cache only after a 30-second minimum floor. Expired login is reported explicitly. Hermes's currently observed local omlx provider has no official quota adapter here; it remains unknown. WorkBuddy quota is unsupported. Quota failures do not invalidate successful local token rows.

Watch mode emits newline-delimited full snapshots. It watches existing Codex sessions, Hermes state.db files, Cursor state.vscdb files, and WorkBuddy projects roots using native fs.watch, debounces 1500 ms, and performs a 300-second fallback scan. Scans are serialized; changes during a scan trigger one follow-up. Newly created or unwatchable roots are covered by the fallback. Stdin accepts one bounded line `{"action":"refresh"}` to request another serialized, debounced scan and quota probe. The Bridge owns process lifecycle and USB isolation. Watch mode is opt-in; once exits after its snapshot.

## Independent Cursor export and freshness

Cursor is excluded from Tokscale graph. Its token reader requests only `https://cursor.com/api/dashboard/export-usage-events-csv?strategy=tokens` using the existing native login in memory. CSV is streamed with a16MiB/30second bound; identifiers and raw CSV are discarded, only dates/model/token counters retained. No shared Tokscale Cursor CSV or credential file is read or written. Export coverage can be limited to a billing cycle, so it is partial and does not erase earlier archived days. Cached rows carry their original `as_of_ms`; local rescans do not make them fresh. Manual refresh has a30second floor; background export300seconds.

Quota requests use direct HTTPS; automatic proxy routing is not enabled. Codex connection failure is `network_timeout`; no estimated quota or stale cache is presented as a successful fresh query. Installed LaunchAgent pins the resolved Node executable in `BOT_NODE`, without copying login data.
